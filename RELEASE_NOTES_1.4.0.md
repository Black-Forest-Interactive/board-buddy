# Board Buddy 1.4.0

## Important: please enter your name once more
Player profiles are now managed by the server instead of the browser. After the update, every player is asked for their display name again. Sessions started with the old profile can't be resumed; please start a new session.

## Security
- **Server-managed player sessions:** Your player identity is a secure, server-issued session that scripts on the page can't read or forge. All actions in a session are bound to this identity.
- **Stricter access to sessions:** Only participants can view a session, its battles and its live updates.
- **Admin access:** The admin app now requires a dedicated admin role.
- **QR codes are generated by Board Buddy itself:** Join links are no longer sent to an external QR code service.
- **Hardening:** Input validation, generic error messages, additional browser security headers and frontend containers running without root privileges.

## Fixed
- **Live updates after reconnecting:** Battle updates no longer stop arriving after all players of a session briefly lost their connection.
- **Clear error responses:** Invalid input now results in a proper error instead of an internal server error.

## Self-hosting changes
- Both frontend containers listen on port **8080** instead of 80.
- Admin users need the Keycloak realm role `board-buddy-admin`.
- New configuration options: `BOARD_BUDDY_BASE_URL`, `KEYCLOAK_JWKS_URL`, `KEYCLOAK_ISSUER`, `KEYCLOAK_ADMIN_CLIENT` (backend) and `KEYCLOAK_ORIGIN` (admin frontend). See [Self-Hosting](docs/installation.md).

## Technical
- GitHub releases are created automatically after a successful build on `master`.
- CI: pinned actions, secret scanning, CodeQL and a dependency audit for the frontend; Dependabot now also covers npm and Docker.
- New security tests for the portal and admin API.

## Also included: changes from 1.3 (not published as a release before)

### New
- **Extra battle points when starting a battle:** The start dialog now has a field for attacker and defender each, so cards that aren't modelled in the game yet can be accounted for. The points are added to the battle hand, and at least one card always stays in hand.
- **Spectator view for more than two players:** Players who aren't fighting stay in the lobby. There they see an "A vs B" card marked "Spectating" and can follow the battle, but can't trigger anything. The fighters' reserves stay hidden from them.

### Fixed
- **Chaos with three or more players:** Uninvolved players used to be pulled into every battle automatically and saw the attacker's data as their own.
- **Battle overwrite:** If a battle is already running, a second one can no longer be started and overwrite it.
- **City defender bonus:** The defender of a city now gets the intended 3 extra cards. Previously the bonus never applied, because the attacker calculation ran for both sides.
- **Stale display:** The battle and lobby views no longer overwrite newer data with an older response that arrives late.
- **Wrong opponent in the lobby:** The lobby now shows the actual opponent in the battle, not simply the first other participant.
- **Back to the lobby:** When no battle is active any more, the battle view returns to the lobby automatically.

### Security
- Only the attacker, the defender or the host can start a battle. Only the participants or the host can cancel or finish it.

### Technical
- Angular 22.2, Nx 23.2, vitest 5, `@ngxpert/hot-toast` 7.
- Micronaut 5.2, Gradle 9.8, Logback 1.6.5, Caffeine 3.3, Simple Java Mail 9.3.5.
- New tests for the battle hand calculation.

### Note on existing games
The city bonus changes how strong city defenders are compared with earlier versions. This affects battles started from this version on.
